1. Git Basics

Git is a version control system that allows you to track changes in your code and collaborate with others efficiently.

Great for:

  • Undoing Mistakes
  • Integration with Other Tools
  • Community and Support

2. Git Config
2.1 git --version

Checks the installed Git version.

git --version
2.2 git config --global user.name

Checks the configured name. To change it, add the name:

git config --global user.name "heguer"
2.3 git config --global user.email

Checks the configured email. To change it:

git config --global user.email "you@example.com"
3. Start a Repo
3.1 git init

Initializes a new Git repository. This command creates a new Git repository in the current directory and sets up the basic files and directories needed to start tracking changes.

git init

Running git init again in the same folder doesn't create a new repo — it reinitializes the existing one. Multiple repos require separate folders, each with its own git init.

git init and git init . do the same thing (. is the default target). git init <path> creates and initializes a new folder instead.

3.2 git config --global init.defaultBranch main

Sets the default branch name for new repositories you create — so now the new name should be main.

What it does: Sets the name Git uses for the initial branch whenever you run git init on a new repo — instead of Git's older default (master), new repos will start with a branch called main.

Why it matters: GitHub, GitLab, and most modern tooling default to main now, so this keeps your local setup consistent with what you'll push to.

Scope: --global means it applies to every new repo you init on this machine going forward — it does not rename branches in repos you already created.

To check branch name:

git config --global init.defaultBranch

The previous might show main as the default name, maybe set globally

To change name (master → main):

git branch -m master main
4. Work on the Repo
4.1 git status

Say we create a couple files in the tracked folder — it will show them as untracked files and ask if you want to include them.

git status
4.2 git add [file/directory]

Prepares the changes for the next commit. This starts tracking a file or directory.

git add filename.txt
4.3 git add .

Adds everything in the repository (new files, modified files, and deletions). The command used most often.

git add .
4.4 git add -A

Adds everything in the repository (new files, modified files, and deletions).

git add -A
4.5 git commit -m "commit message"

Creates a new commit with a message describing the changes made, capturing the changes made to your local repository.

git commit -m "Initial commit"
4.6 git log

Shows a list of all commits in the repository — displaying the author, date, and commit message for each.

git log

At the very bottom you'll see something like this:

~
(END)
commit e36ad272b950404daa3e38fee01c0343d53119cb (HEAD -> master)
Author: heguerack <heguer76@gmail.com>
Date: Tue Aug 4 16:50:13 2026 -0600

    add all files at once, to be tracked

~

From here we can get the commit id. Using the commit id from git log, we can jump to that snapshot — basically going back to that point in time.

5. Git Advanced
5.1 Moving to a different commit (DOM) 
git checkout e36ad272b950404daa3e38fee01c0343d53119cb

This takes us to that point in time — the snapshot.

5.2 git checkout .

Say you're working on the project and don't want those changes. Instead of going back to a specific commit, use git checkout . to discard changes and start over.

6. GitHub

To work with others remotely. So far it's been local dev — when you run git init, you initialize locally.

6.1 Start a repo on GitHub

Make sure your local repo is on main or master first.

6.2 git remote add origin 
git remote add origin https://github.com/frankdmosquera/mastering-git.git
git branch -M main
git push -u origin main

This is the first block GitHub gives you when pushing an existing repo from the command line — you can run all three at once.

7. Branching
7.1 git branch

Lists all the branches in the current repository. Shows the current branch you're on, highlighted with an asterisk.

git branch
7.2 git branch new-branch

Creates a new branch, but doesn't switch you to it.

git branch new-branch
7.3 git checkout new-branch

Switches you to the newly created branch.

git checkout new-branch
7.4 git checkout -b new-branch-name

Creates the branch and switches you to it in one step. Note: it branches off whatever branch you're currently on — not necessarily main — so be careful depending on what you're doing.

git checkout -b new-branch-name
7.5 git branch new-branch-name some-other-branch

Creates a branch from a selected branch — no need to checkout first.

git branch new-branch-name some-other-branch
8. Local Commits vs (Cloud) GitHub
8.1 git push --set-upstream origin feature-branch

Pushes to GitHub and keeps things in sync. git push -u origin feature-branch is an alternative shorthand.

git push --set-upstream origin feature-branch
8.2 git push

Once linked, you can just run:

git push
8.3 git pull

Fetches changes from the remote repo. If someone makes changes on GitHub, this brings you up to date.

git pull
9. Merging Back to Main

The idea: sync main so it gets the changes from feature-branch, once the feature is tested and confirmed good.

  • Go to "Compare and pull requests" or "Pull requests" in the nav menu
  • Click "New"
  • Compare: feature-branch (from) → base: main
  • It will show something like: "Showing 1 changed file with 11 additions and 0 deletions"
  • If everything looks good, click Create pull request
  • The team lead or senior dev reviews and clicks Merge pull request
  • Confirm merge
  • At this point, the feature-branch can be deleted — everything is in main on GitHub

But here's the catch: locally, you still have that extra branch, and main hasn't been merged locally either! Just run git pull — all the GitHub changes become active locally.

10. Typical Workflow
  • Clone the repo
  • Create a new branch from main (or another branch)
  • Make your changes
  • Push the branch to the remote repo
  • Open a pull request
  • Merge the changes
  • Pull the merged changes into your local main branch
